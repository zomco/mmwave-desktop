# ADR-0008：本地短片是主回查路径

[English](0008-local-clip-review.md)

- 状态：已接受
- 日期：2026-09-27
- 取代：[ADR-0003](0003-nvr-authoritative-media_CN.md) 中「主回查必须 seek NVR」的结论

## 背景

公寓值班员往往在事后、说不清时间地点时翻录像。盒式 NVR 时间轴即使在原厂客户端里也很慢。毫米波融合已经能判断何时、何处有一条像人的轨迹。这个索引只有在抓拍或短片能立刻打开时才有用。

ADR-0003 正确地拒绝了第二套全时录像库。它并不要求每次回查都去 seek NVR。

## 决策

1. 常驻服务是产品运行时。关掉回查界面不得丢掉雷达历史。
2. 主回查媒体是 `enter`、`dwell`、`traverse` 发生时从直播流切下的抓拍和短片，存在本地磁盘。
3. NVR 仍是可选冷存档。ISAPI 检索和导出保留，但不是默认回查，界面必须标明可能很慢。
4. 跟踪、区域事件和轨迹评分来自 `mmwave-engine` 包（`mmwave_engine`）。运行时不依赖 Home Assistant 或 `mmwave-fusion` 集成。
5. 只测距或只有有人/无人的传感器可以做开关与门，不进入融合轨迹。
6. 服务默认只监听 `127.0.0.1`。Windows、macOS 和 Linux LTS 以后台服务运行。本决策不要求签名安装包。

## 后果

只有 NVR 的部署不再宣称降低误报。没有直播 RTSP 时仍有雷达事件，但没有可播放的抓拍。融合回查环需要已安装的 `mmwave-engine`，或本仓库旁的那份源码。
