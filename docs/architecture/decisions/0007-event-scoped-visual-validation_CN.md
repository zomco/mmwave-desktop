# ADR-0007：事件级本地视觉验证

[English](0007-event-scoped-visual-validation.md)

- 状态：已接受
- 日期：2026-08-15

## 背景

真机验证表明，即使海康越界规则已经优化，仍可能产生孤立误报，并且在 iVMS-4200 原生回放中找不到任何越界目标。人工审阅标记、按时间聚合，以及要求非发烧友用户持续调优 NVR 规则，都不能消除这类检索成本。因此，仅靠 NVR 元数据无法提供给事件排序所需的独立证据。

仓库边界禁止在 Python 中解码/渲染视频，也禁止建设第二套全量录像库。但产品仍需要一个可选的本地验证器，只检查已索引 NVR 事件附近的小段录像，不持续扫描或保留全部录像。

## 决策

把事件级本地视觉验证作为 Desktop 的可选能力：

- NVR 继续作为权威媒体存储，其事件仍是不可变的元数据书签；
- 只允许对已有事件请求分析，并且只读取有界上下文窗口；不会扫描完整录像库，也不会在 Desktop 关闭时运行；
- FFmpeg 继续负责视频解码和派生 WebP 证据。Python 可以编排 FFmpeg，并把有界、固定尺寸的 BGR 张量转换后用于本地 ONNX 推理；Python 不实现视频编解码器，也不渲染帧；
- 检测器和短窗口跟踪器生成目标轨迹；确定性几何阶段把轨迹落地点与 NVR 事件审计中已有实证的越界线或多边形进行比较；
- 结果属于辅助证据，明确区分：确认触发、存在目标但未匹配触发、未检测到支持目标、无法判断、组件不可用或分析失败。负面证据绝不删除或修改 NVR 事件；
- 界面可以把确认结果优先排序，并允许用户显式只看确认事件。在另行批准、具备真机针对性的验证门禁之前，禁止自动执行不可逆排除；
- 分析完全在本地运行。帧、凭据和回放定位符不发送到云端推理服务，也不写入 SQLite；缓存记录只保存有界摘要、模型身份和可选派生证据路径；
- 模型/运行时代码及再分发权重必须分别完成许可证、来源、哈希和维护评估。未安装可选模型/运行时时，基础应用仍可运行。

## 影响

TraceCue 可以在不建设第二套录像库的前提下，为核心 event-to-trace 工作流增加独立证据。事件分析会增加 CPU/GPU 负载、可选安装包体积，以及新的模型质量失败模式，尤其是在夜间、眩光、遮挡或高压缩画面中。“未检测到支持目标”的证据弱于正向重建出的越界行为，界面必须保留这一限定。

首个实现只覆盖越界侦测和区域入侵，并仅识别 COCO 中的行人/车辆类别。扩大产品承诺前，每个模型版本都必须使用明确获准的昼夜真机样本进行评估。全量录像 embedding、通用视频理解和云端上传继续保持在范围之外。
