# ADR-0004：TraceCue 单仓采用 MIT 许可证

[English](0004-licensing-before-contributions.md)

- 状态：已接受
- 日期：2026-08-12

## 背景

仓库创建时使用 GPL-3.0。此前产品规划建议 desktop/gateway 产品整合闭源、engine 可能开源。GPL-3.0 可以商业销售，但其源码及下游义务可能与该边界冲突。选择模式前接受第三方贡献，可能导致日后难以重新许可。

## 待评估选项

1. 整个单仓保持 GPL-3.0，通过分发、支持和硬件商业化；
2. engine 使用宽松/开放许可证，desktop/gateway 在按目录或仓库隔离后使用专有许可；
3. 在所有者控制下双重许可，并使用明确贡献者协议；
4. 仓库保持私有/专有，未来再开放选定模块。

## 决策

所有者已将整个 TraceCue 单仓，包括 `desktop`、`gateway`、`engine` 和 integrations，重新许可为 MIT License。包元数据必须声明 `MIT`。除非后续已接受 ADR 引入不同模块边界，外部贡献按相同 MIT 条款提交；本决策不要求贡献者许可协议或双重许可授权。

第三方组件继续适用各自许可证。尤其是，捆绑 FFmpeg 不会改变 TraceCue 的 MIT 许可证，也不会消除 FFmpeg 的 LGPL 义务。每次二进制发布必须保留精确的第三方声明、许可证文本、来源记录和对应源码获取方式。

## 后果

- 仓库根目录 `LICENSE` 是 TraceCue 代码许可证的事实来源。
- 包 manifest、贡献指南和发布元数据必须与 MIT 保持一致。
- 外部贡献不再受本 ADR 阻塞，但仍需正常评审、作者权利确认及许可证/安全检查。
- 若未来引入专有或双重许可模块，必须有明确的取代 ADR 和清晰的权属记录。
- FFmpeg 及其他第三方分发义务继续作为独立发布门禁。
