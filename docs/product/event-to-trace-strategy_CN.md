# 从事件到轨迹的策略

[English](event-to-trace-strategy.md)

## 产品决策

在 NVR 优先版本中，**目标区域**是用户通过画面选择的摄像机集合；界面按录像机分组，并在本地保存稳定的 TraceCue 摄像机 ID。自由文本区域名不是实际检索条件，因此不再显示。历史筛选条件保存摄像机集合和可选归一化事件类型，下次只需换时间窗即可加载。持久 Trace 会话固定这些条件，让用户围绕“昨晚、前一晚或前后 3 晚”等不确定时间反复逼近。结果按稳定 ID 累积去重，未查看、已查看、已排除和候选状态在重启后仍保留。检索结果在证据中保留 NVR 原始分类，但界面只显示本地化行为名、事件时间、摄像机和检索会话身份。第一页会自动加载缓存 JPEG 预览，光标移入时再按需加载缓存的 3 秒 WebP 动图；用户也可用小时事件密度快速聚焦。用户把有效结果提升为候选片段，最后下载确认后的 MP4。本版本明确不接受自然语言检索输入。

这是当前海康 NVR 上最务实的推荐方案。它能够产生实际价值，同时不会假装粗粒度录像元数据已经包含精确物理轨迹。

## 方案评估

| 方案 | 成熟度 | 价值 | 局限 | 决策 |
| --- | --- | --- | --- | --- |
| 可视摄像机集合 + NVR 报警日志 + 历史筛选 | 使用稳定本地数据和有实证的历史端点 | 用户通过画面识别地点；事件时间可映射回连续录像 | 报警日志支持/保留期依固件而异；仍可能误报 | 已在有实证的海康固件实现 |
| 读取 NVR 事件规则、计划和联动 | 厂商/ONVIF 存在相关操作 | 解释哪些事件来源已开启、通道怎样配置 | 端点/权限不同；配置不能证明历史上发生过事件 | 现在实现只读审计，并按固件扩充证据 |
| ONVIF 事件拉取/订阅 | 标准有 `GetEventProperties`/`PullMessages`，Profile 规定事件一致性 | 获得跨厂商实时 topic/source 数据 | 通常是实时而非历史归档；桌面关闭会漏事件 | 以后只与常驻生产者结合 |
| 厂商精细历史事件检索 | 部分固件/功能提供 | 获得更细事件身份，不把长录像文件误当事件 | 不通用；必须按型号/固件实测并限制请求 | 已实现 ISAPI 报警日志适配器；按型号扩充证据 |
| 对全部录像做 CV/向量检索 | 组件本身成熟 | 可搜索 NVR 规则之外的视觉语义 | 算力、存储、隐私成本高；形成第二条分析流水线并带来新误报 | 不进入 NVR 优先版本 |
| Gateway/雷达融合 | TraceCue 架构已支持持久外部 Interval | 可提供独立的移动/轨迹证据 | 需要常驻生产者和经认证实体硬件 | 后续里程碑，不进主导航 |

ONVIF 在[操作索引](https://www.onvif.org/onvif/ver20/util/operationIndex.html)发布了相关标准操作。海康也发布按型号区分的 ISAPI 能力/事件资料，例如其[开放硬件文档中的智能规则能力](https://open.hikvision.com/hardware/XMLs/DEVICE_ABILITY_SmartCalibrationCap.html)。这些资料都不足以支持“所有 NVR 存在一个通用历史事件端点”的假设。

## 已实现的 event-to-trace 闭环

1. 设备中心自动发现候选设备，并用用户凭据验证所选设备；
2. 通道别名为稳定摄像机赋予“北门”等业务含义；
3. 只读审计区分普通 `motion`/`video_tamper` 与 Smart `line_crossing`/`region_intrusion`，记录启用/联动状态，并绘制设备返回的有界栅格/多边形/越界线覆盖层；选择 Smart 类型时只保留有支持证据的摄像机；
4. 事件检索提交有界时间窗、可跨多台 NVR 的可视摄像机集合和可选归一化事件类型；检索历史报警日志，连续录像文件不会成为事件候选；
5. TraceCue 在安全证据中保留原始报警日志 `metaId`，同时映射为本地化的 `motion`、`video_tamper`、`line_crossing` 或 `region_intrusion`；不暴露模糊的“其他智能事件”和连续录像筛选；
6. 若未找到目标，同一会话追加相邻夜间时间窗；结果累积去重，审阅状态用于缩小剩余工作量。
7. 分页结果自动生成并缓存原子 JPEG 预览；光标移入时生成有界 3 秒 WebP 动图；确认结果可生成候选 MP4；
8. MP4 记录保留安全的检索/事件来源，导出历史始终可理解。

## 证据边界

- 通知/规则已启用，表示设备被配置成能够产生该事件，不代表历史上已经发生；
- 报警日志条目只是 NVR 来源的书签，不是独立高置信验证；连续录像分类只用于解析书签周围的媒体；
- TraceCue 关闭时错过的实时事件，除非 NVR 有经过验证的历史端点，或常驻 Gateway 已保存，否则无法重建；
- 栅格、多边形和越界线覆盖层仍属于摄像机/规则配置。它们可以解释所选规则，但不能证明某个历史录像 Span 一定由该规则触发。

## 下一步证据里程碑

1. 为每组受支持型号/固件记录脱敏的审计、检索、回放证据；
2. 将有证据的历史报警日志适配器扩充到更多型号/固件与事件类别；
3. 仅当设备返回稳定身份时，才把事件 rule ID/画面区域与检索记录关联；
4. 使用获准的人工标注数据测量 event-to-clip 耗时和重要事件召回率，再讨论是否优于原生客户端。
